# 班级白板实时协作

每个班级只有一套长期共享的多页白板，服务端从登录用户的班级关系确定房间，不接受客户端指定班级。师生均可书写、擦除、清屏和增删页面，翻页和主题独立。个人白板在加入协作时暂存在当前应用内存，退出账户恢复，个人内容不会自动上传到班级。

## 启动

1. 按 `server/.env.example` 配置 MySQL 和服务端。运行 `npm run server`（或 `npm run account`），启动时自动执行 `003_class_whiteboards.sql` 和 `004_whiteboard_operations.sql`。
2. 前端运行 `npm run dev`；远程客户端设置 `VITE_ACCOUNT_API_URL` 为它们可访问的账户服务地址。HTTPS 网页对应 `wss://`；反向代理需允许 WebSocket Upgrade，空闲超时应大于 60 秒。
3. 教师注册班级，学生用邀请码加入。双方登录后自动连接，右上角显示连接／保存状态。

当前服务为**单实例房间所有者**。不要让多个账户服务进程同时承载同一班级白板：数据库快照不能替代跨实例消息路由及写入协调。后续扩容需先实现按班级路由或独立协作服务。

## 协议

`POST /api/v1/whiteboard/ticket` 使用现有 Bearer 身份验证，返回有效期 30 秒、一次性的连接票据。浏览器连接 `/api/v1/whiteboard/ws?ticket=...`，握手前再次核实班级。每 20 秒发送心跳并复核成员关系，60 秒未收到客户端消息/Pong 则断开。

客户端命令通用字段：`opId`、`pageId`、`epoch`。服务端操作额外包含班级单调递增的 `revision`。页面清屏增加 `epoch`；过期操作明确拒绝，防止清屏后旧笔迹复活。

| 消息 | 内容与行为 |
| --- | --- |
| `stroke_start` | 笔迹 ID、样式与首点立即广播；断线中的笔迹可以携带已采样点恢复预览 |
| `stroke_points` | 新增点与 `offset`，约 16ms 一批，单批最多 256 点；不重复发送整条笔迹 |
| `stroke_commit` | 收笔先 flush，再提交完整笔迹；完整数据允许在断线后可靠重试 |
| `canvas_clear` | 当前页清屏、增加 epoch、取消该页活动笔迹 |
| `page_add` / `page_delete` | 页面集合共享；不强制其他人翻页；至少保留一页 |
| `undo` / `redo` | 服务端查找该用户在当前页／版本的最近操作；只改变明确的笔迹 ID |
| `strokes_visibility` | 撤销／重做结果；不整体覆盖页面。清屏的撤销恢复当时被清除的内容，保留随后新增笔迹 |
| `snapshot` | 完整已保存页面、当前活动笔迹、revision 与进程内 generation |
| `snapshot_updated` | 持久操作保存成功后的版本通知；正常客户端已消费增量，无需重复拉全量 |
| `sync` | 请求 generation、since 之后的事件；房间保留最近 512 条事件，超出窗口回退全量快照 |
| `ack` / `error` | 重复已确认命令返回 ack；版本冲突、容量上限等明确反馈 error |

新连接和重连先获取完整快照，包含正在书写的笔迹；连接内出现版本缺口时用增量回放修复。用户／班级变更会关闭旧连接，旧回调不能修改新班级状态。

## 绘制与保存

- 固定 1920 × 1080 逻辑画布，等比适配窗口并居中；坐标和笔宽与设备像素密度无关。
- 本地笔迹立即绘制，移动按动画帧刷新；远端点按帧合并绘制。16ms 是发送间隔，不是端到端延迟保证。
- 橡皮擦作为有顺序的笔迹操作保存。服务端确定提交顺序，所有客户端按相同顺序重绘。
- 每次完整笔迹、清屏、页面增删和撤销／重做，都在 MySQL 原子写入完整班级快照之后再广播确认。无需等待定时快照，所有已确认操作都可跨重启恢复；活动预览不写数据库。
- 未确认的完整命令以原 opId 在浏览器内存及 sessionStorage 暂存，按用户和班级分开；重连重发、服务端通过独立 SQL 操作记录持久去重，快照与操作记录在同一事务提交。每个窗口队列最多 100 条／约 2MB，满时提示并保留当前笔迹，不继续接受新笔迹。
- 服务端断开连接时移除该连接的临时预览；客户端尚未收笔的笔迹在重连后恢复预览，已收笔的命令重新提交。
- 清屏以前的待同步操作会被拒绝并显示原因，不会覆盖更新后的白板。
- 个人撤销包含笔迹／橡皮擦和清屏；增删页面不进入撤销历史。清屏建立新的撤销范围。最近 1000 条全班操作历史可用于个人撤销，失去历史引用的隐藏笔迹会清理。

## 当前容量与边界

每班最多 100 页、200,000 个保存点、100 条并发活动笔迹；单笔最多 16,000 点。保存点包括仍可撤销的隐藏笔迹，清屏后会保留上一批内容供撤销。操作去重记录长期保存在数据库，内存仅缓存最近一部分，不限制班级累计使用次数。单连接每秒最多 240 条消息、消息最多 2MiB；客户端发送积压超过 512KiB 时重连恢复。活动房间上限 2000，空房间释放内存，后续从数据库恢复。

浏览器 sessionStorage 失败时会提示用户保持页面打开；网络恢复前关闭窗口可能丢失尚未保存的内容。服务端保存失败不确认，会保留客户端待重试命令。主题不共享，师生使用不同底色时需要选择双方可见的笔色。

## 验证

- `npm test`：既有测试加协作状态、真实指针事件分批、DPR 坐标、抬笔前发送、清屏取消、队列持久化、重连及班级切换测试。
- `npm run build`：TypeScript 与 Vite 构建。
- `cargo test --manifest-path server/Cargo.toml`：协议状态机以及现有账户流程（账户集成测试使用原有专用 MySQL 测试库）。
- `cargo build --manifest-path server/Cargo.toml` 后运行 `npm run test:whiteboard:integration`：需要已创建的 `virtuallab_whiteboard_test` 数据库；也可以设置 `WHITEBOARD_TEST_DATABASE_URL`，数据库名必须以 `_test` 结尾。测试在 18081 端口启动自己的服务，创建独立测试用户，不清空已有班级数据。

集成测试覆盖：认证、真实师生连接、抬笔前广播、正在书写时加入、班级隔离、重复提交、个人撤销／重做、清屏并发、页面增删、增量回放、进程重启恢复及 50 个连接。
